# Marketing landing page (+ /refund)
Status: done · Phase: pre-launch · Last updated: 2026-10-24

## What it does
- `/` (on the one origin `https://wapee.online`) is a static, pre-rendered marketing page: header, hero, who it's for, how it works, features, pricing (plans + add-ons + compare table), FAQ, CTA band, footer (Terms, Privacy, Refund, support email).
- `/` is the static landing page for EVERY visitor (signed in or not; no redirect). Auth-aware header: an inline `<head>` script (`authSession.ts`, types stripped, no network, no SDK) reads `sb-<ref>-auth-token` from localStorage (also chunks / `base64-` / `{currentSession}`); a valid, NOT expired session sets `html[data-auth="in"]` and `window.__landingUser`. CSS then shows the signed-in variants (name + "Dashboard" in header and mobile menu; hero + final CTA "Go to Dashboard" to `/today`) and hides "Log in" / "Start free trial"; secondary CTAs stay. An inline script right after the header fills `[data-user-name]` with textContent. Expired (even with a refresh token) / malformed / no JS = signed out. Native app: `app/index.tsx` still redirects to `/today`; in-app (client-side) navigation to `/` does too. PWA `start_url` stays `/today`.
- `/refund`: Refund Policy, same look as /privacy and /terms; reseller = Polar Software, Inc. (merchant of record), cancel by emailing support.
- Legal pages (`/privacy`, `/terms`, `/refund`): no DRAFT banner, only a "Last updated" line (privacy/terms: date in the HTML; refund: `REFUND_UPDATED` in `build-landing.mjs`). Governing law Pakistan. Privacy processors: Supabase (Seoul, South Korea), Vercel, Resend, Polar, the browser's push service (no Expo row: native push has no EAS `projectId`; no Google row: Google sign-in is off on prod; no Cloudflare). No backup claim until Supabase Pro (founder decision 2026-10-24). Operator line "Wapee is operated by Abdullah, Lahore, Pakistan." on terms + privacy from `brand.operator` (`{{operator}}`; name must match the payment KYC). Not lawyer-reviewed.
- Support email everywhere = `brand.supportEmail` (now `wapeeglobal@gmail.com` until `support@wapee.online` forwarding is confirmed). The DB Auth hook text still says `support@wapee.online` (never shown; matched by regex only).

## Business rules
- **Plan buttons carry the choice** (2026-10-24): each pricing card links to `/signup?plan=<key>&interval=month|year` (follows the monthly/yearly toggle) and, for a signed-in visitor (`auth-in` variant, "Choose this plan"), to `/settings/billing?plan=…&interval=…`. Built by pure `planChoiceHref` (pricingModel); `paths.billing` in the page context / build script. The app saves it (see billing.md "Plan choice before signup").
- **No price in code.** Plans and add-ons come at runtime from `get_public_pricing()` (GET, anon key). Skeleton while loading, friendly error + retry + support email on failure, noscript note. A unit test fails on any price literal in the landing source, strings or build script.
- Plan cards / compare table are built from `plans.features` = the SAME flags `business_has_feature()` gates on. `embed_widget` is never shown (off at launch; `HIDDEN_FEATURES`). Add-on availability: `addons.available_plans` (null = every plan); a plan whose features flag the add-on key includes it (custom roles: Team add-on, included in Business).
- Yearly toggle shows annual / 12 per month + "Billed X per year"; "N months free" is computed and only shown when every plan agrees. Business shows "per location" when `priced_per_branch`.
- Honesty: no SMS, widget, online payments, custom domain, waitlist, testimonials, logos, stats or compliance claims (tested on the rendered text).
- Launch prices (dev, set by the migration; USD/month, yearly = 10x): Solo 15 (1 staff), Team 39 (5 staff/location), Business 79 per location; add-ons Packages 9, Inventory 9, Files & Photos 9, Forms & Consent 12, Client portal 12, Custom roles 10.

## SEO (2026-10-12)
- **Full tag set on `/` and `/refund`** (`chrome.ts`'s `head()`): canonical, `meta robots` (`index, follow` by default, overridable), Open Graph (incl. `og:image:width/height`), Twitter `summary_large_image` card, favicon/apple-touch-icon. Title ≤60 chars, description ≤160 (both checked by `landing.test.ts`; shortened `meta.description` in `en.json` from 167→139 chars to fit).
- **`privacy.html`/`terms.html`** (the two static legal pages, NOT built from `chrome.ts`) got the same canonical/robots/OG tags added directly to the templates, with a new `{{siteUrl}}` placeholder filled by `build-landing.mjs`.
- **JSON-LD on `/`**: `SoftwareApplication` (unchanged, pre-existing — ships with NO `offers` at build time; `landingClient.ts`'s `updateJsonLd()` already adds real `offers` from `get_public_pricing()` once it resolves client-side, so the build script does **not** fetch pricing a second time), plus new `Organization`, `WebSite`, and `FAQPage` (built from the SAME `ctx.s.faq.items` the rendered FAQ section reads — `landing.test.ts` asserts the JSON-LD text matches the page text exactly, interpolated).
- **OG/Twitter image**: `scripts/ogImage.mjs` renders a brand-style 1200x630 PNG (wordmark + hero tagline, same colors as the hero) via `sharp` at build time → `dist/icons/og-image.png`. `sharp` is a real `dependencies` entry (not `devDependencies`): it only runs inside the Node build script, never imported by the shipped app, but Vercel's `npm ci` can skip `devDependencies` depending on `NODE_ENV`, so it has to be a real dependency to be safe.
- **robots.txt / sitemap.xml**: `Allow: /` plus `Disallow` for every top-level route under `app/(app)`, `(admin)`, `(auth)` and the guest-token pages (`/*/manage`, `/*/portal`, `/*/review`, `/*/sign`, `/*/book`) — derived from the real route files at build time (`topLevelRouteNames()` in `build-landing.mjs`), not hand-maintained, so it can't silently drift. Sitemap stays scoped to `/`, `/privacy`, `/terms`, `/refund` (no per-business `/<slug>` entries — out of scope, would need a dynamic sitemap endpoint).
- **Private app routes noindex**: new `NoIndexHead` (`src/components/shared/NoIndexHead.tsx`, web-only) mounted once in each of `(app)/_layout.tsx`, `(admin)/_layout.tsx` and the NEW `(auth)/_layout.tsx` (that group had no layout before — added only to host this, `headerShown: false` matches the root Stack's existing default, no other behavior change). This sets `<meta name="robots" content="noindex, nofollow">` **client-side**, after the JS bundle runs — it does NOT appear in the static HTML a crawler fetches over plain HTTP, because every private route is served by the same pre-built `_app/shell.html` (an empty `<div id="root">`). The real, reliable signal for those routes is the `X-Robots-Tag: noindex, nofollow` HTTP **header** added in `vercel.json` (sent before any HTML), covering the same private route list plus `/:slug/(manage|portal|review|sign|book)`.
- **`/<slug>/book`**: stays `noindex, nofollow` on purpose — the business **website** at `/<slug>` is the indexable page (`WebsiteHead.tsx`: already had dynamic title/description/canonical/OG/LocalBusiness JSON-LD, untouched this round). `/book`'s title/description are now dynamic (branch name once `useBookingPage` resolves, falling back to the slug) purely for link-preview cards when the direct booking link is shared — not for search.
- **Expo web SEO limitation (see `_handoff.md` for the short version)**: `expo-router/head` (used by `NoIndexHead`, `WebsiteHead`, `/book`'s own `<Head>`) patches `document.head` **client-side only**. A crawler that does not execute JS, or is slow to, sees only what `+html.tsx` / the pre-rendered static HTML already contains. This is why `/` and `/refund` are pre-rendered as real static HTML (no React) and why private routes rely on the `X-Robots-Tag` HTTP header, not the meta tag alone.
- New tests: `landing.test.ts` extended (robots/Twitter/OG dimensions, title/description length with the REAL brand name, JSON-LD block presence + FAQPage text-match, legal template placeholders); new `seo.test.ts` (OG image is a real 1200x630 PNG by reading the PNG header bytes directly — no image-decoding dependency; `vercel.json`'s private-route header list and `build-landing.mjs`'s robots.txt derivation both stay in sync with the real `app/(app)+(admin)+(auth)` route files, same derivation pattern `reservedSlugs.test.ts` already used; every layout mounts `NoIndexHead`; `/book` stays noindex).
